## Fixture và quy trình chung

Test tự động: [test_qq01_03_review.py](../../../../services/ai/tests/test_qq01_03_review.py). Mỗi parametrized case có ID riêng trong [JUnit](../../../../qa/evidence/qq01-03-review-2026-10-16/reviewer-cases.xml).

Fixture mặc định là `mock_research_request()` trong `services/ai/examples/growth_lead_request.py`: TripC MOCK, English-speaking newcomers, offer mock, profile version 1, snapshot/source version 1, source approved **TEST**, quote `The guide compares living areas for newcomers.`, URL `https://example.org/qq04-mock`, fetched_at có timezone, synthetic=true. Mỗi case đổi job UUID, SQLite ở thư mục pytest riêng. Không lấy TEST approval để duyệt nguồn thật.

Các ca model double dùng `ObservedProvider`: ghi request gửi provider và trả JSON có kiểm soát. Mục tiêu là thử validator khi model trả output xấu; không coi model double là bằng chứng model thật tự chống mọi prompt injection.

Các bước chung của nhóm request:

1. Dựng fixture, chỉ thay trường được mô tả ở dòng test.
2. POST `/internal/v1/runs`; lỗi preflight kiểm HTTP/error code và số provider calls = 0.
3. Nếu accepted, poll GET đến completed/failed; kiểm findings/evidence/missing_facts/calls.
4. So sánh kỳ vọng bên dưới. Không coi HTTP 202 là pass nếu output cuối sai.
